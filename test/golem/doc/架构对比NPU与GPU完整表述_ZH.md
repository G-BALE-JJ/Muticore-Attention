# 我们的架构相对 NPU 脉动阵列与 GPU 的创新与优势（完整版）

## 1. 问题背景与定位
在大模型推理与矩阵计算场景中，常见两类方案各有明显边界：
- 纯 NPU 脉动阵列：算力密度高、能效好，但数据流形态较固定，跨算子和跨任务的调度弹性有限。
- 通用 GPU：生态成熟、通用性强，但在特定工作负载下，数据搬运与同步行为较难做细粒度可控优化。

我们的体系并非简单复刻上述任一方案，而是采用 CPU + 可编程阵列 + NoC + 分布式 HBM 的协同架构，在可编程性、可扩展性与可观测性之间做联合优化。

## 2. 核心创新（可直接作为论文贡献点）

### 2.1 计算与数据移动协同，而非单点算力优化
相较“只追算子峰值吞吐”，本架构将计算、DMA 发起/等待、任务管理、NoC 传输、内存后端访问统一放在一套运行时与统计闭环内。

直接价值：
- 能准确识别瓶颈位于 compute、dma_issue、dma_wait、task 管理，还是 NoC/HBM。
- 优化路径更清晰，不会陷入“算力高但系统端吞吐不上去”的常见陷阱。

### 2.2 组级控制与请求调度机制
通过组级管理与请求调度机制，将多核心并发请求进行整形与配额控制，使高并发下的系统行为更可控。

直接价值：
- 降低突发请求造成的队头阻塞与抖动风险。
- 提升大规模并发时的稳定性和可预测性。

### 2.3 分布式内存节点与 NoC 感知的数据路径
内存不是单一“黑盒带宽池”，而是显式建模为多节点分布式体系，并通过 NoC 进行路由与映射。

直接价值：
- 计算扩展可与内存扩展协同推进。
- 对带宽不均衡、热点端口、队列延迟等问题具备结构化调参空间。

### 2.4 体系级可观测性
提供执行分解、NoC 指标、内存延迟分布、压力指标（例如轮询与重试）等多维数据。

直接价值：
- 便于做架构-运行时-任务的联合优化。
- 研发迭代更快，验证结论更可复现。

## 3. 相对 NPU 脉动阵列的优势

### 3.1 更高的任务与数据流弹性
NPU 脉动阵列通常在固定数据流与固定算子模板下效率极高，但跨任务形态变化时适配成本上升。

我们的优势：
- 通过运行时调度与 DMA 管线化策略支持更灵活的任务组织。
- 在算子组合、规模变化、并发模式变化下，适配空间更大。

### 3.2 不止优化阵列利用率，而是优化系统端有效吞吐
纯阵列利用率高并不代表端到端快，瓶颈可能在搬运、同步、访存。

我们的优势：
- 以端到端执行分解为目标函数，避免只优化阵列而忽略系统瓶颈。
- 更适合真实部署中“多瓶颈并存”的工作负载。

### 3.3 扩展路径更系统化
传统 NPU 设计在扩展时易受片上存储和固定访存通道约束。

我们的优势：
- 通过 NoC 与分布式内存节点进行扩展，具备更明确的规模化路径。
- 在中大规模并发场景下，更容易保持稳定性能曲线。

## 4. 相对 GPU 的优势

### 4.1 数据移动与同步路径更可控
GPU 的硬件调度强大但内部行为相对黑盒，针对特定工作负载做细粒度确定性控制难度较高。

我们的优势：
- DMA 发起、等待、轮询、请求调度等路径可显式观测和调优。
- 对时延敏感或确定性要求高的场景更友好。

### 4.2 领域专用优化深度更高
GPU 面向通用负载，很多设计必须折中。

我们的优势：
- 可围绕目标任务在架构和运行时层直接加专用机制。
- 在目标域内更容易获得性能/能效/稳定性的综合收益。

### 4.3 跨层协同效率更高
GPU 生态中跨硬件-运行时-应用层联合优化通常成本较高。

我们的优势：
- 统一技术栈便于快速闭环：问题定位、机制修改、实验验证一体化。
- 适合学术与工程并重的快速迭代路线。

## 5. 边界与适用场景（建议答辩时主动说明）

### 5.1 我们的优势最强于“目标域”而非“全域通用”
当任务模式与架构机制匹配时，收益明显；但在高度通用且生态绑定强的场景，GPU 仍具软件生态优势。

### 5.2 系统级优化带来更高设计复杂度
可调参数和协同路径更多，意味着工程治理与验证体系需要同步完善。

### 5.3 结论应坚持数据驱动
建议始终以三类指标联合报告：
- 性能：吞吐、端到端时延、尾延迟
- 资源与系统：NoC 拥塞、HBM 带宽与均衡、队列延迟
- 稳定性：重试、轮询、跨规模抖动

## 6. 可直接用于汇报的简版结论
我们架构的核心价值不是“替代 NPU 或 GPU”，而是在可编程性、系统扩展性与可观测性之间建立新的平衡点。

相较 NPU 脉动阵列，我们在数据流弹性与系统端瓶颈治理上更有优势；相较 GPU，我们在目标域任务上的数据移动可控性、跨层协同效率和确定性优化空间更大。

因此，该架构特别适合需要持续迭代、强调端到端性能稳定性、并且希望进行架构-运行时协同优化的专用计算场景。

## 7. 一句话版本（用于开场）
我们的创新在于把“算子加速”升级为“系统协同加速”：不仅提高算力，还把数据移动、调度、网络与内存一起纳入可编程、可观测、可优化的统一框架。
