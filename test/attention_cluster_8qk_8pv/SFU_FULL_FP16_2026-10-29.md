# SFU 默认全 FP16 内部模式

SFU 的全部默认入口统一为全 FP16 内部计算；无需设置环境变量。
`GOLEM_SFU_INTERNAL_PRECISION=fp32` 可显式选择历史数值路径。
配置由 `cpu_builder.py` 传入每个 worker 的 `golem.SFU.internal_precision`，
实例启动时输出 `[SFU_PRECISION] core=… internal=… rounding=…`。
所有 worker 应使用同一模式。

```bash
# 默认使用全 FP16；也可在原有实验命令前显式指定。
GOLEM_SFU_INTERNAL_PRECISION=fp16 <原有 runner 及参数>

# 显式恢复旧数值模式。
GOLEM_SFU_INTERNAL_PRECISION=fp32 <原有 runner 及参数>
```

这是 SFU 内部数值格式选项，与 FP16/FP32 张量传输 dtype 独立。
它覆盖 Attention score 缩放、MAX/EXP/SUM、online softmax 的 m/l 及
alpha/beta/乘加/倒数/归一化，Add、Multiply、SiLU、RoPE、RMSNorm，
以及 primitive、旧 softmax tile/row、跨 worker softmax 归约入口。
矩阵阵列的累加精度不由这个选项改变。

## 数值规则

- 全 FP16 模式下，每个运算的输入和结果均量化为 IEEE binary16，使用
  round-to-nearest, ties-to-even，保留次正规数、正负零、Inf 和 NaN。
- 内部 `float` / `double` 是模拟器的宿主容器，保存的可见运算结果为
  binary16 可表示值；归约或 online 状态不借用 FP32/FP64 精度。
- 使用独立 `SFUArithmetic` 转换，直接从宿主容器舍入，避免 double→float→half
  二次舍入，并处理原存储 helper 在半个最小次正规数附近的截零差异。
  原有张量存储 helper 保留，因此旧模式不受此修正影响。
- Add/Multiply 每次运算舍入；SiLU 按 `negate → exp → +1 → reciprocal → multiply`
  各步舍入；RoPE 的两个乘积先分别舍入，再对加减结果舍入，没有隐式 FMA。
- RMSNorm 的平方、每次 SUM、除以宽度、加 epsilon、RSQRT、两次乘法都舍入。
  epsilon 和宽度作为运算输入也先量化。RSQRT 是一个 SFU 运算，仅对其结果舍入；
  不额外插入独立 SQRT 的舍入点。
- SUM 保持各入口原来的功能遍历/归约顺序，每次累加均舍入。
  此次没有将功能循环改成 RTL reduction tree；跨 worker 归约沿用现有到达顺序。
- EXP/LOG/TANH/RSQRT 由宿主数学函数求值后舍入到 binary16。
  这不是指定 LUT、多项式、厂商 IP 或 RTL 的位精确实现。

## 数值结果与资源边界

全 FP16 会改变输出。例如 SiLU 输入 -12 时，EXP(12) 在 binary16 溢出到 Inf，
后续倒数得到 0，最终为负零；旧模式仍得到非零负数。
顺序累加 4096 个 1，在 binary16 下到 2048 后无法继续增加。
RMSNorm 的平方溢出、epsilon 下溢及长序列 softmax 的归约误差同样按该规则保留，
没有隐藏的混合精度回退。

现有 lane 数、latency、II、有限队列、FIFO 元素数、端口及传输计费保持原参数。
内部缓冲仍用宿主容器承载；此次没有把物理 SRAM/FIFO 打包成 16-bit，
也没有推导面积、功耗或吞吐收益。FP16 单元的资源预算和时序若要不同，应另行配置
并验证；不能仅凭减少数值位宽声称 cycles 减半。

旧数值 verifier 通常以原 FP32 内部算法为参考，FP16 模式应使用对应的逐步舍入
参考。新模式尚未通过完整 LLM 端到端精度/质量验收；历史 selected prefill 配置需要基于新默认模式重新验收，
不更新其固定 guest/library 哈希或历史性能结论。重建库后，固定哈希入口需要重新验收。

## 试验区验证（移植前）

本节保留 `Muticore-Attention-all-gemm` 的历史验证证据及原始源码路径；
这些结果不代表公共主项目四阶段均已通过。公共移植验证见
[四阶段 FP16 同步回归](../../docs/SFU_FP16_INTEGRATION_2026-10-29.md)。

```bash
python3 -m unittest discover \
  -s test/golem/small/muticore_attention \
  -p 'test_sfu_arithmetic.py' -v
python3 -m unittest discover \
  -s test/golem/small/muticore_attention \
  -p 'test_sfu_internal_precision.py' -v
```

`test_sfu_arithmetic.py` 对所有有限正/负 binary16 值、相邻值中点及其中点两侧、
溢出边界和特殊值，与 NumPy 独立转换进行比较。
`test_sfu_internal_precision.py` 从当前生产 `sfu.cc` 构建测试库，在 SST 事件循环中
执行真实 SFU，GM 用测试内存替代，不模拟 HBM/NoC 性能。
逐项检查 FP16 参考、默认/显式 FP16 一致，以及相同资源下的完成调度一致。
夹具的模拟周期仅作调度回归，不是加速器性能测量。


初始双精度实现验证（切换默认值之前）：原有 180 项生产路径回归、新增 4 项精度测试、6 项 host SFU audit 通过。
新增测试覆盖 253,956 个转换输入，14 组实际 SFU 功能结果匹配逐步 FP16 参考。
从改动前 HEAD 的 SFU 源码另建测试库，FP32 的全部结果和完成调度与当前版本相同。

[验证记录、源码/库哈希及运行说明](progress_results/2026-10-29/sfu_fp16/validation.json)；
