# Master B 角色说明（C++ Runtime Owner）

适用范围：LeNet 当前执行链路 + 后续 GCN 算子执行。

---

## 1. 你负责什么

- 负责目录：`small/`（重点 `small/lenet5` 及相关 runtime）。
- 负责目标：按 plan 正确执行算子与同步协议，并输出可观测日志。
- 你是“执行正确性” owner。

---

## 2. 你不负责什么

- 不负责 ONNX 解析和 bin 生成。
- 不负责 SST 平台拓扑与 DRAM 配置。

---

## 3. 你的输入与输出

- 输入
  - 前端给的 bin + plan
  - 编排层给的 `GOLEM_*` 运行参数
- 输出
  - 可执行程序
  - 阶段里程碑日志
  - 运行结果（HBM 输出）

---

## 4. 你每天做什么（建议）

1. 先跑最小算子回归（单 stage）。
2. 再跑端到端链路（多 stage）。
3. 遇到问题先做阶段隔离（conv1/conv2/fc 分开验证）。
4. 修复后保证日志字段不破坏 stats 脚本解析。

---

## 5. 你的质量标准（DoD）

- 算子执行与同步协议正确（ready/reduce 顺序正确）。
- 关键 stage 有稳定里程碑日志。
- 与前端 reference 对拍通过（容差内）。
- 不引入接口破坏（宏/env/layout 与编排约定一致）。

---

## 6. LeNet 例子（你如何工作）

- 执行 `conv1 -> conv2 -> fc1 -> fc2 -> fc3`。
- 确保 post-op 写回与读回链路一致。
- 通过里程碑日志帮助系统 owner 定位阶段问题。
- 在 ONNX 主线下做到端到端 PASS。

---

## 7. 面向 GCN 的扩展方式

- 在 runtime 中新增通用 op 实现（例如 SpMM）。
- 尽量复用已有调度/同步骨架，避免模型专用分叉。
- 新 op 先做功能正确，再做性能优化。
