# LeNet5 项目管理汇报（一页版）

## 一、项目现状（结论先行）

- 已完成单次仿真端到端链路：`conv1 -> pool1 -> conv2_repack -> conv2 -> pool2 -> fc1 -> fc2 -> fc3`。
- 已实现真实数据集接入与二进制后端打包，运行流程可复现。
- 已具备阶段化观测能力：支持里程碑日志与阶段延迟报表输出。
- 当前“数值一致性”已通过（硬件路径 vs Python 参考）。

## 二、系统能力与价值

- **工程能力**：模型解析、任务切分、后端排布、仿真执行、统计分析已闭环。
- **平台能力**：支持按阶段追踪瓶颈，支持参数化架构调优（DMA/NoC/核心映射）。
- **组织能力**：形成跨层接口（plan/layout/ABI）作为统一协作契约，适合多人并行开发。

## 三、当前主要瓶颈

- 第一瓶颈：`conv2_im2col`（分布式重排阶段）
- 第二瓶颈：`conv2_gemm`
- 说明：瓶颈核心是“跨节点搬运与重排成本”，不是算力不足。

## 四、风险与边界

- **风险1（口径）**：阶段统计需持续保证与 `VANADIS_CPU_CLOCK` 一致换算。
- **风险2（接口）**：plan/layout/ABI 若变更未同步，容易出现跨层错配。

## 五、团队分工（四人不重叠）

- **A：算子编译与后端排布**（模型解析、bin打包、plan生成）
- **B：C++执行运行时**（conv/fc执行、同步协议、里程碑）
- **C：SST平台参数层**（拓扑参数、稳定性、日志治理）
- **D：验证与性能分析**（回归、阶段报表、瓶颈定位）

## 六、两周推进计划（可执行）

- **W1：语义闭环**
  - 接入 ONNX Runtime 真值锚点；完成“标签一致性”判定报告。
  - 固化阶段统计口径（含时钟一致换算）。
- **W2：性能优化**
  - 聚焦 `conv2_im2col` 优化（访存批量化/缓存化）。
  - 给出优化前后对比（阶段延迟、总时延、稳定性）。

## 七、管理决策建议

- 以“接口稳定（plan/layout/ABI）+ 指标驱动（阶段延迟）”作为主线管理机制。
- 所有改动必须同时通过：
  - 数值一致性门禁
  - 阶段性能回归门禁
