# FFN Boundary and HBM Audit (2026-10-23)

## Result

The current two-layer prefill critical path is concentrated after Attention:

| Measurement | One FFN array group | Two FFN array groups | Change |
| --- | ---: | ---: | ---: |
| One worker, full-width FFN + residual | 1,894,700.625 | 1,858,703.625 | -1.90% |
| 16 workers, MPI8, full-width FFN + residual | 1,982,194.0 | 1,967,583.5 | -0.74% |
| Full prefill, token IDs through final logits ACK | 6,134,778.375 | 6,084,167.75 | -0.82% |

The third row was measured with the existing fused two-layer stack, changing only
the FFN array-group schedule from one to two. All three workloads use formal
S=1024, H=2048 and FFN=8192. The full-stack candidate passes decoder numerical,
lifecycle, banked-GM, resource and all-GEMM reuse-window verification. All 128
QK jobs, 2,560 PV windows and the expected QKV/Wo/Gate/Up/Down/LM windows are
covered. The greedy token remains 99037.

The two-group schedule is validated as a configuration, not adopted as the
default. Its full-stack gain is modest, so the runner remains explicit opt-in.
It uses the same 64 arrays, one context per array and 2 MiB GM. Array
programming increases while compute is interleaved; the two-wave broadcast
candidate was slower in the single-worker screen and was rejected.

## Critical Path and HBM

The full-stack interval contains 4,438,442,840 HBM read bytes and 33,812,600
HBM write bytes. The read total is overwhelmingly model weights and
coefficients (4,422,172,672 bytes). Activations and panels account for
15,794,176 reads and 33,554,432 writes; logits account for a further 256,512
write bytes. Thus the current stack still depends on substantial HBM weight
traffic and retains output materialization required by the workload contract.

Across the two layers, PV output O causes 8 MiB of HBM writes followed by
8 MiB of reads before Wo consumes it. The producers are workers 12-19, while
Wo consumers are workers 4-19. Eliminating this 16 MiB opportunity requires a
bounded cross-worker redistribution path, GM landing, ownership publication
and ACK ordering. Disabling those DMA operations alone would be incorrect.

Final RMSNorm overlaps decoder tail work by 46,780.75 cycles; its exposed tail
is 41,563 cycles. The critical-path analyzer now charges only exposed work,
while reporting the full stage span and overlap separately.

## PV-to-Wo Runtime Handoff

The opt-in `--pv-wo-gm-handoff` path covers the measured
`S=1024, H=2048, 32 query heads, 8 KV heads, Dh=64` shape. Each of 16 Wo
workers owns 64 query rows and receives 32 head blocks of 8 KiB. Per layer,
512 payloads carry 4 MiB over the existing, byte-accounted control NoC.
The PV producer remains busy until the destination acknowledges the timed
GM writes. The receiver rejects duplicate heads, enforces the next layer
generation, and publishes a complete 32-head mask before Wo can consume it.

Reception uses `[0x1a0000,0x1e0000)` of each existing 2 MiB worker GM.
The earlier proposed `0x70000` interval was rejected because Attention still
uses it for V panels. The tail interval is free during Attention; Projection
and FFN can reuse it in their separate phases. Wo first relocates the complete
256 KiB tile to its ordinary input arena through timed GM reads and writes.
Head-major Dh=64 order already matches the GEMM K-panel layout. The relocation
preserves that order and releases the tail before FFN scratch reuse; its cost
is 4 MiB of GM reads plus 4 MiB of GM writes per layer, in addition to the
4 MiB of GM landing writes. No new SRAM or array operand context is added.

The routing contract is at
`results/ffn_boundary_audit_20261023/pv_wo_handoff_contract.json`. Runtime
results and source/library provenance are under
`results/pv_wo_handoff_20261023/full/`.

Tests cover delayed GM ACKs, NoC retry, duplicate rejection, two generations,
byte-varying payloads, and all worker destinations. A real DecoderOpJob test
poisons HBM O and verifies that both the legacy Wo loop and the reuse-window
Wo path produce the same correct bits with zero O-input DMA. DMA-verifier
tests reject missing/duplicate landings, late ACKs, and any residual O HBM
read/write, while excluding Projection/FFN reuse of the same GM addresses.
The baseline suite passes 235 tests; all 18 existing decoder tests and the new
Wo test pass.

The full SST simulation completed in 1008.35 wall seconds. Its initial host
verification passed numerical checks but rejected the GM ledger because it
included Projection writes before Attention started. The verifier now uses
Attention root acceptance through Wo start as the GM ownership interval;
host-only verification on the unchanged completed simulation artifacts now
passes, including lifecycle, numerical, resource, banked-GM and all-GEMM
window coverage checks. Projection/FFN writes outside Attention are excluded
by explicit root-acceptance and Wo-start ownership boundaries.

This implementation removes the entire 16 MiB O HBM roundtrip across two
layers. Both final Y and final RMSNorm are bit-identical to the two-group
control (2,097,152 FP16 elements each). However, total latency increases
72,078 cycles (+1.185%). Wo span increases 7.51% in layer 1 and 5.05% in
layer 2. Attention becomes slightly faster, while later stages also change
with the new memory/NoC schedule. The exact cause is not isolated by this
single comparison; timed GM relocation and prefetch/port contention are the
next profiling targets. The handoff remains explicit opt-in and is not a
performance-default recommendation.

The compact evidence is `results/pv_wo_handoff_20261023/summary.json`, with
complete transport accounting in `hbm_audit.json` and a same-control ledger
in `control_hbm_audit.json`. The original failed host audit remains in
`driver.log`; final verifier hashes are recorded separately without changing
simulation provenance.

This is one completed fusion boundary, not a claim of HBM-free prefill.
Q/K/V panel materialization, model weights, embedding input/output, final
outputs and logits still use HBM. A useful next change is to profile and
reduce the 256 KiB-per-worker GM relocation while preserving Wo weight
prefetch and array overlap, then rerun the same comparison. Broader panel
fusion should be evaluated independently after that boundary is efficient.
