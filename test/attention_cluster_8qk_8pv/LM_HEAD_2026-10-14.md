# 最后一个 token 的 LM head 与 M=1 尾行

计算路径为 `两层 Decoder → 独立 final RMSNorm → 读取 token 1023 → LM head → vocab logits 写回 HBM`。所有权重仍为可独立验证的合成数据，硬件执行完整 dense tile。

## 线性算子的尾行

`DecoderOpJob` 现在支持非 256 倍数的 M。每组使用 `min(64, remaining rows)` 条 array 和对应大小的输入 scatter、输出读取及写回；GM packing stride 随有效行数变化，不对不存在的行做 HBM DMA。64 行及 256 行的原 Decoder 路径保留。

M=1 模式将输出 tile 按 16 个 worker 分配：worker index 为 `manager + 4*lane`，之后每 16 个输出 tile 取一个。每个 worker 仅激活一条 array，读取一个 hidden 向量；这是功能基线，之后可以优化词表维度的 array 并行使用。

现有 96 B DecoderOp 描述符保留大小，在原保留字段中加入 `output_tile_begin`，用于访问整张权重矩阵中的全局输出 tile。矩阵存储仍按输出 tile 跨四节点 stripe。每个 N 块最大 8192 列；最后一个块按 64 列补齐，填充词表行权重为零。host 丢弃填充 logits。

## 内存容量与地址

用户要求每节点 2 GiB 容量。LM head runner 默认 `--node-mib 2048`，也支持显式选择 128、256 等 2 的幂容量。容量参数同步传给统一 C++ allocator、guest projection/Decoder/final norm/LM head、Attention node stride、SST 节点地址区间和 preload/backing。worker GM 仍为 2 MiB，WCP C-buffer 仍为 1 MiB。

2 GiB 是存储大小，GB/s 是带宽。四个数据节点合计 8 GiB，另有 node 0 的 OS 地址空间。本步不调整链路带宽，也不修改当前约 4 GiB/backend 的 Ramulator2 几何。实际模型数据按原 4 KiB 对齐 allocator 分配；扩大节点只改变节点基地址及上限。

正式词表 128256、hidden=2048，head 权重 FP16 为 501 MiB，四节点分片各 125.25 MiB。它与当前两层、scratch、final norm 和 logits 一同驻留，原 128 MiB/node 容量会在启动前被拒绝。

## 同步与输出

Root 等 final norm 所有输出及 completion ACK，定时 DMA 清零 16 个独立 head completion flags，ACK 后发布 head release epoch=4。worker 循环提交 stage=11，每块 epoch=`4+chunk index`，仅最后块写自身 completion。正式词表为 16 块（最后块 5376 列），最终 epoch=19。Root 收齐 16 个 epoch=19 标志后打印唯一成功完成。

所有 worker 读 node 4 的 final 输出第 255 行，即全局 token 1023。词表输出按 worker tile 所有权写到相应数据节点，host 从四节点恢复完整一维 logits。不同 worker 可交叠词表块；同一 worker 在上块输出 ACK 后才能复用 scratch。

## 验证和计时

保留两层与 final norm 的完整检查，新增逐块 worker/epoch、独立 flags、last-token 输入地址与长度、所有 weight tiles 地址与字节覆盖、全部 logits 唯一输出覆盖、completion 在最后块输出 ACK 后发布及 root 完成检查。输出初始化为 NaN；有效 logits 必须完整且有限，填充列必须为零。

局部参考对实际 final hidden 执行同精度 CPU linear oracle，要求精确匹配。组合参考从 X0 独立计算两层、final norm 和最后 token 的 head，阈值 0.006。有效 logits 写入 `last_token_logits.npy`；此步不执行采样。

生产 `DecoderOpJob` 的 API test doubles 检查 M=1、2、65、257，包括全局 tile offset、有效 array 数量、输入/输出不访问填充行，以及没有输出 tile 的 worker 正确完成。SST 小尺寸词表 8201 检查 8192+9 的有效列尾块（补齐后 64 列），正式尺寸检查完整 128256 词表和 2 GiB/node 路由。

canonical 边界为 `第一层 X 首次 input DMA send → 最后 token 的 logits 最后 output DMA ACK`。head 从第一次 last-token 输入 DMA 到最后 logits ACK 的周期包含权重读取、GM、array programming/compute 和输出搬运；交接单独统计。排除 host 初始化、启动以及最终输出 ACK 后的通知/退出。

## 已完成结果

三个 LM head case 均为 PASS：128 MiB/node 的 hidden=256、vocab=8201 检查输出分块与 9 个有效列尾块；2 GiB/node 的 hidden=256、vocab=9 检查单 tile 和其余 worker 的空工作完成；2 GiB/node 的 hidden=2048、vocab=128256 检查完整词表。

| Case | head 交接 cycle | head cycle（含 DMA/GM/array） | 整条链路 cycle | 1 GHz 延迟 |
| --- | ---: | ---: | ---: | ---: |
| vocab=8201, hidden=256 | 9,788.25 | 12,161.875 | 1,029,074.875 | 1.029075 ms |
| vocab=9, hidden=256, 2 GiB/node | 10,039.375 | 1,342.625 | 1,023,075.625 | 1.023076 ms |
| vocab=128256, hidden=2048, 2 GiB/node | 9,849.25 | 1,339,615.75 | 19,937,207.75 | 19.937208 ms |

正式尺寸 16 × 16=256 个 head worker job 全部完成，16 个独立 flag reset ACK 完整；head 输入和权重实际读取 526,385,152 B，logits 输出 256,512 B，完成 ACK 时序及覆盖检查均通过。最终局部参考误差为 0，完整链路组合参考最大绝对误差为 0.000244140625。归一化完成边界为 18,587,742.75 cycles，head 尾部合计 1,349,465 cycles，占整条链路约 6.77%。各边界取同一次运行，不用历史不同 guest 的两层总时长相减。

每节点 allocator 使用 240,807,968 B（229.652374 MiB），容量上限 2,147,483,648 B。实际配置 `GOLEM_MEM_NODE_SIZE_BYTES=2147483648`、HBM backing 文件大小、guest stride、head 最后 token 和跨四节点权重读取均由正式仿真验证。

正式 SST wall 为 1,773.053324 s，约 29 分 33 秒；完整 host 校验 wall 为 52.003530 s。此前 final norm 仿真 wall 为 1,516.297035 s，约 25 分 16 秒。这些 wall time 是宿主机运行时长，与模拟的 19.937208 ms 推理延迟不同。

15 项 host 布局/数值/同步检查测试、26 项生产算子尾行/相关资源/配置回归测试全部通过，合计 41 项。原 final norm 入口重编译后完成小尺寸 SST 回归，产物 `results/lm_head_20261014_legacy_final_norm` 为 PASS。

`summary.md`/`summary.json` 汇总通过结果；`provenance_audit.json` 核对每次运行保存的 22 个 source snapshot hashes、guest、library 和 logits；`input_comparison_audit.json` 确认前两层与 final norm preload hashes/offsets 相同；`legacy_regression_result.json` 保存旧入口回归结果。首个小尺寸之后修改了 runner 的默认 node 容量，因此首例源码 snapshot 与现在的 runner 有这项差异，原快照和对应 hashes 完整保留。
